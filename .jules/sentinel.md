
## 2024-05-20 - [Zip Slip Path Traversal]
**Vulnerability:** Tar extraction logic in `pane-api/panespec/container.go` passed untrusted header names to `filepath.Clean` and `filepath.Join`, enabling zip slip vulnerabilities.
**Learning:** `filepath.Join` in Go does not inherently sandbox paths to a specific root directory. If the untrusted input contains `../` sequences that break out of the directory structure when evaluated relative to the current directory, it escapes the expected base path (e.g. `filepath.Join("/base", "../../etc/passwd")` resolves to `/etc/passwd`).
**Prevention:** Always prefix untrusted archive entry paths with `/` before calling `filepath.Clean` to force absolute path resolution, trim the leading slash, and then join with the base directory to safely confine extraction.
## 2024-06-30 - [Path Traversal in Image Management]
**Vulnerability:** `pane-api/panespec/images.go` contains path traversal vulnerabilities in image name handling (e.g. `RemoveImage`, `InspectImage`). The name input does a simple `strings.ReplaceAll` for `/` and `:` but doesn't prevent inputs like `.` or `..`, leading to arbitrary file deletion or access within the context of the user running the API.
**Learning:** Sandboxing functions like `secureJoin` are insufficient when user-supplied identifiers (e.g., image names) are directly evaluated as `.`, `..`, or empty strings. `filepath.Join("/base", "..")` resolves exactly to `/base`, which `secureJoin` considers "secure" because it hasn't escaped `/base`. However, operations like `os.RemoveAll` on the resolved path will delete the entire base directory.
**Prevention:** Explicitly validate identifiers (like image names or container IDs) using strict allowlists or regex (e.g., `^[a-zA-Z0-9_.-]+$`) and explicitly reject `.`, `..`, and empty strings *before* path construction.
