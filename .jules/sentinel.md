
## 2024-05-20 - [Zip Slip Path Traversal]
**Vulnerability:** Tar extraction logic in `pane-api/panespec/container.go` passed untrusted header names to `filepath.Clean` and `filepath.Join`, enabling zip slip vulnerabilities.
**Learning:** `filepath.Join` in Go does not inherently sandbox paths to a specific root directory. If the untrusted input contains `../` sequences that break out of the directory structure when evaluated relative to the current directory, it escapes the expected base path (e.g. `filepath.Join("/base", "../../etc/passwd")` resolves to `/etc/passwd`).
**Prevention:** Always prefix untrusted archive entry paths with `/` before calling `filepath.Clean` to force absolute path resolution, trim the leading slash, and then join with the base directory to safely confine extraction.
## 2024-05-20 - [Path Traversal in Image Deletion]
**Vulnerability:** The `RemoveImage`, `InspectImage`, and `PullImage` functions construct file paths using user-supplied image names directly without validating for empty strings or path traversal sequences (`.` and `..`). In `RemoveImage`, this allows an attacker passing `..` to invoke `os.RemoveAll("/var/lib/pane")`, deleting the entire base directory.
**Learning:** `strings.ReplaceAll` for `/` and `:` is not sufficient to prevent path traversal if `.` and `..` are allowed. Furthermore, since `PullImage` strips URI prefixes before processing, an input like `pane://` is reduced to an empty string, which `filepath.Join` evaluates to the base directory. Sandboxing via `secureJoin` is insufficient for `.` and `..` because they resolve to the base directory itself.
**Prevention:** Always use strict input validation explicitly rejecting empty strings, `.`, and `..` before any path construction using user-controlled identifiers for file system operations.
