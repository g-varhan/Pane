
## 2024-05-20 - [Zip Slip Path Traversal]
**Vulnerability:** Tar extraction logic in `pane-api/panespec/container.go` passed untrusted header names to `filepath.Clean` and `filepath.Join`, enabling zip slip vulnerabilities.
**Learning:** `filepath.Join` in Go does not inherently sandbox paths to a specific root directory. If the untrusted input contains `../` sequences that break out of the directory structure when evaluated relative to the current directory, it escapes the expected base path (e.g. `filepath.Join("/base", "../../etc/passwd")` resolves to `/etc/passwd`).
**Prevention:** Always prefix untrusted archive entry paths with `/` before calling `filepath.Clean` to force absolute path resolution, trim the leading slash, and then join with the base directory to safely confine extraction.
## 2026-06-29 - [Base Directory Deletion via Unsanitized Empty/Self-referencing Paths]
**Vulnerability:** `RemoveImage` and `InspectImage` in `pane-api/panespec/images.go` accepted empty string (`""`), current directory (`.`), and parent directory (`..`) as image names. Even though `/` was sanitized, `.` or `..` combined with `filepath.Join` caused `os.RemoveAll` to delete the root image directory (`/var/lib/pane/images` or its parent) instead of a specific image.
**Learning:** Sanitizing path separators (e.g., replacing `/` with `-`) is insufficient for operations operating directly on a base directory because it doesn't prevent exact matches to `.` or `..`, which resolve directly to the base directory and its parent when passed to file operations like `os.RemoveAll`.
**Prevention:** Always implement strict equality checks against `""`, `.`, and `..` when user-supplied identifiers are appended to a base path, especially before executing destructive operations like `os.RemoveAll`.
