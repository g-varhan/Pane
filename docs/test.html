Comprehensive Testing Guide

Pane is composed of three decoupled core layers: pane-vmm (C, raw hypervisor ioctls), pane-core (Rust, state machines & cgroups), and pane-api / pane-cli (Go, schema config & OCI converter). To ensure stability, high performance, and zero regressions, Pane maintains a comprehensive test suite across all three tiers.

1. Automated Test Suites

Go CLI & Configuration Tests (`pane-api` / `pane-cli`)

The Go tests cover schema validation, configuration merge precedence rules (CLI overrides > yaml config > metadata defaults), and container layer extraction whiteouts mapping.

# Run all Go tests including OCI layer conversions
go test -v ./...

Key test case: TestPullContainerImage dynamically pulls docker://busybox, unpacks layer tarballs, compiles the guest init statically on the host, creates an ext4 disk image using mke2fs, and downloads the Firecracker kernel.

Rust Core Orchestrator Tests (`pane-core`)

The Rust test suite verifies VM state transitions, cgroup v2 resource limit enforcement, vsock command execution framing, eBPF TC networking rules, and parent snapshot forking benchmarks.

# Run all Rust unit and integration tests
cd pane-core
cargo test

Key test cases:

  • test_cgroups_lifecycle_and_limits: Checks cgroup v2 memory/CPU throttle hooks.
  • test_fork_50_vms: Benchmarks cloning 50 VMs from a snapshot in under 2 seconds.
  • test_agent_exec_success: Tests vsock connection execution rounds on loopback.

C Hypervisor Library Tests (`pane-vmm`)

The C tests directly exercise raw KVM ioctls, memory slot allocations, virtio-mmio setup, and benchmark io_uring performance against synchronous sys calls.

# Run all C backend tests
cd pane-vmm
make test

Key benchmarks:

  • test_create_destroy: Spawns and destroys 1,000 VMs sequentially to guarantee zero file descriptor (FD) leaks.
  • test_firecracker: Validates that VM boots a 64-bit payload within the target limits (< 5ms).
  • test_uring_bench: Confirms that io_uring read throughput exceeds synchronous syscalls by at least 15% (typically ~150-200% improvement).

2. Manual Integration Testing

To verify the entire CLI end-to-end integration with the active API daemon, execute the following manual testing steps:

Step 1: Start the API Daemon

Fire up the Pane daemon specifying a writeable local UNIX socket:

# Start the daemon in the background
pane daemon start --socket /tmp/pane.sock &

Step 2: Pull Test Images

Verify that different image schemes resolve and download correctly:

# 1. Local copy test (copies/links Tiny10 Windows image & VirtIO drivers)
pane pull tiny10

# 2. Remote CDN download test (downloads Alpine Virt ISO)
pane pull alpine

# 3. OCI/Docker container conversion test (pulls, flattens, formats)
pane pull docker://alpine:latest

Step 3: List and Inspect Image Metadata

Check if the local cache registers and exposes the specs correctly:

# List all cached images and virtual disk sizes
pane images

# Inspect spec defaults for the container-derived image
pane image inspect alpine-latest

Step 4: Dry-Run VM Boot

Verify that CLI flags merge cleanly over image metadata:

# Test merge precedence: CLI overrides memory and vCPUs
pane run --dry-run --cpus 4 --memory 2GiB alpine-latest

Step 5: Run VM & Exec Commands

Boot the VM and execute a loopback command via vsock:

# Spawn the VM
pane run --name app-vm alpine-latest

# Execute shell command inside the guest VM
pane exec app-vm -- uname -a

# Stop and reclaim resources
pane rm app-vm
